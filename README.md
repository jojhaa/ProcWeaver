# ProcWeaver

面向 Windows 平台的高性能进程与业务级智能分流客户端。  
基于 **Tauri 2 · Rust · React · TypeScript · Mihomo** 深度构建。

---

## 项目概述与设计理念

ProcWeaver 是一款专注于多业务场景网络精细化调度的桌面客户端。它将节点订阅管理、Windows 进程代理、业务规则包系统与域名专属 DNS 解析无缝整合于轻量高效的现代化桌面界面中。

### 为什么需要业务级分流？

在现代软件工程、AI 辅助研发及多任务协同环境中，开发者与重度网络用户经常面临复杂的出站需求：
- **多业务出口冲突**：特定大模型 API 或敏感开发环境对落地节点的地理位置与网络纯净度有严格要求，而日常办公与媒体流量则偏好低延迟或本地连接。若使用全局切换，往往牵一发而动全身。
- **后台子进程漏流**：现代开发工具（如各类 IDE、CLI 命令行程序、构建脚本）在运行时通常会动态派生多级后台进程（例如 Language Server、后台编译 Worker、Git 进程）。传统代理工具仅匹配主程序的可执行文件名，导致大量关键子进程漏走直连。
- **规则共享与隐私冲突**：传统配置中，规则逻辑、节点凭据与个人订阅通常混合在一起，难以安全地向团队或社区分发业务规则。

为了彻底解决这些痛点，ProcWeaver 提出了**“业务规则包”**机制：将属于特定业务的一组主进程、子进程树与关联域名打包管理，让特定业务独享专属出口，其余未匹配流量平稳遵循现有系统规则，实现互不干扰的精细化治理。

## 方案对比

| 对比维度 | 传统代理客户端方案 | ProcWeaver 业务规则包方案 |
| :--- | :--- | :--- |
| **规则组织维度** | 基于单个域名或独立端口配置，规则分散庞杂 | **以业务为中心**，将进程、子进程与域名聚合为一个独立规则包 |
| **节点绑定机制** | 规则与具体节点硬编码绑定，更换节点维护成本高 | **定义与出口插槽解耦**，规则包仅声明出口用途，本机自由绑定节点 |
| **子进程处理** | 仅识别主窗口进程，动态派生子进程容易漏走直连 | **智能进程树穿透**，支持自动识别并纳管当前及后续衍生的多级子进程 |
| **DNS 污染防护** | 全局统一 DNS 或单向防污染，难以针对业务精细控制 | **专属域名 DNS 护航**，支持为指定域名配置独立 DoH/DoT 与专属出站节点 |
| **规则分享安全性** | 导出文件常夹带节点密码、订阅密钥等隐私信息 | **安全导出机制**，自动剔除所有本地凭据与私有绑定，放心分享 |
| **系统资源占用** | 常见重型前端框架封装，后台常驻内存较高 | **Tauri 2 + Rust 原生驱动**，超低系统内存占用与后台开销 |

## 核心特性全景

### 📦 业务规则包系统
- **业务矩阵聚合**：支持将一组关联的桌面应用、后台服务及关联 Web 域名整合在同一个业务规则包中，一键统管。
- **出口用途抽象解耦**：规则包内部仅定义“主出口”与“DNS 出口”插槽，用户导入后可在本地直观选定具体节点或策略组进行绑定，实现规则与节点资产的分离。
- **零凭据安全共享**：导出时自动剥离任何本机节点名称、凭据密钥及订阅地址，保证规则分享的安全性与纯粹性。

### 🌲 深度进程树感知与启动代理
- **多级血缘进程跟踪**：不仅能够依据可执行文件名称或完整绝对路径匹配主进程，更提供“包含未来子进程”选项，全自动持续识别其派生的多级后代，彻底杜绝后台流量泄漏。
- **一键代理注入启动**：针对支持应用级代理参数或环境变量（如 `HTTP_PROXY`、`ALL_PROXY`）的开发环境，可直接从 ProcWeaver 界面注入配置拉起应用。

### 🛡️ 域名专属 DNS 护航
- **独立加密解析出口**：可针对特定业务域名（如 OpenAI 关联 API）配置专属的安全 DNS 服务器（DoH / DoT），并强制 DNS 查询经由指定出口节点发送。
- **解析与流量解耦调度**：域名 DNS 查询出口可灵活配置为跟随主出口，亦可独立指定，确保在彻底隔绝 DNS 污染的同时不改变实际业务访问规则。

### 📊 全链路运行观测看板
- **透明化核心状态**：实时监控网络核心运行状态、并发活跃连接、实时上下行吞吐曲线与核心系统日志。
- **命中规则精准追溯**：连接面板清晰记录每条请求的源进程路径、匹配的规则包名称以及最终命中的出站节点，排障一目了然。

### ⚡ 原生轻量架构
- **系统级原生能力**：采用 Rust 与 Tauri 2 技术栈重构桌面架构，启动迅速，内存占用极小，保障多任务开发环境下的系统流畅度。
- **成熟稳定内核**：依托经过工业级验证的高性能 Mihomo 代理核心，保障网络协议兼容性与高并发稳定性。

## 技术运行边界与设计原则

为保证系统运行的高可靠性，ProcWeaver 遵循以下产品边界与安全设计：

1. **流量接管前提**：分流调度以流量成功进入代理核心为前提。应用层模式需依赖目标程序遵循系统代理或支持手动代理配置；已有建立的长连接不会在规则切换时强行中断迁移。
2. **状态分级呈现**：客户端明确区分展示“规则已保存”、“运行配置已应用”与“已观察到命中”，连接未命中不代表程序无网络，可结合连接日志进一步核对。
3. **安全防回退机制**：未完成节点绑定的规则包严禁启用，绝不生成存在歧义的局部规则，防止因配置缺失而静默回退至全局直连或非预期出口。
